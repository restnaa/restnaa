# M4 implementation plan

Scope: functional local workflows on the existing design; no M5 release audit, analytics service, network, notification action buttons, or JavaScript scheduler.

1. `src-tauri/src/history.rs`, `storage/mod.rs`: typed today/seven-day history with Rust/system-local calendar boundaries, distinct category/outcome counts, daily summaries and at most 100 recent events. Seven days includes today and the preceding six local dates; use acted-at time, exclude future events. Aggregate all matching events, not just the displayed recent list. Transactionally delete only break_events after explicit confirmation. Preserve scheduler metadata, settings, and active reminders.
2. `scheduler/service.rs`: extend the existing worker channel with history read/clear requests; retain exclusive connection ownership and serialize deletion with scheduler transitions. Emit `history-changed` after successful deletion; frontend also refreshes on committed outcomes, window focus/visibility and explicit Refresh. No polling timers.
3. `settings.rs`, `commands.rs`, `build.rs`, permissions: backward-compatible persisted onboarding completion; typed get_history/clear_history commands with required confirmed=true. Main-only history grant, no break-window deletion capability. Existing validated settings/pause commands remain authoritative. Save forms merge current native/pause fields to avoid overwriting those independent controls.
4. `lib/types.ts`, `lib/api.ts`, `hooks/useHistory.ts`: typed DTOs/events, cancellation and stale response guards. `App.tsx` opens setup for incomplete onboarding, navigates to dashboard only after successful save. Setup reuses schedule controls and existing native notification/startup controls; autostart stays explicit opt-in.
5. `components/ScheduleForm.tsx`, `PauseControls.tsx`, `HistorySummary.tsx`, pages: editable independent toggles/intervals/work days/hours/quiet mode, validated Save settings applies without restart; all pause durations, tomorrow/manual and resume. Dashboard renders real deadlines, real today counts, current break and manual eye/movement actions. Settings includes native test notification and confirmed deletion. History offers Today/Last seven days, totals by outcome/category, dates and bounded event details; honest empty/loading/errors.
6. `BreakPanel.tsx`, shared styles/layout: keep Rust-owned Start/Done/Snooze/Skip and Esc behavior for both categories. Suggested durations are text, not fake countdowns. Semantic forms, labels, focus management, native modal confirmation with keyboard focus containment and cancel default, visible focus, responsive layout and reduced-motion support. No guilt labels, invented progress percentage, mock chart or placeholder count.

Tests before acceptance: Rust calendar/DST/local-day boundaries, both categories/all outcomes, seven-day aggregate beyond recent limit, future exclusion, delete confirmation/capability and transactional preservation; existing scheduler/native regressions. Frontend tests for settings validation/save errors, onboarding completion and persistence, pause variants, real history/error/empty states, cancel/confirm deletion, event refresh and break actions. Playwright browser-only error/keyboard tests plus explicitly mocked IPC workflow tests (test fixtures only), desktop/compact and reduced motion. Run formatting, strict Clippy, Rust tests, lint, types, frontend tests/build and UI tests. Build/launch native app for actual command smoke checks; never erase existing user history for QA. Record failures and unresolved native/manual gates precisely.

Implementation notes: history requires no schema migration; the existing settings JSON gains a backward-compatible completion flag. History totals stream all matching rows; only event details are bounded to 100. On compact layouts the same semantic outcome table becomes cards, showing every outcome without sideways scrolling. The SQLite connection remains exclusively worker-owned, including history operations.

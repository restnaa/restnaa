# M2 scheduler implementation plan

Scope: Rust scheduler and typed integration only. No native notifications, tray, autostart, additional windows, settings forms, history analytics, or full break workflows.

1. `src-tauri/src/clock.rs`: injectable UTC/monotonic samples and local timezone conversion. Production uses system local time; tests use a controllable clock and timezone. Resolve ambiguous work boundaries explicitly and move nonexistent boundaries to the first valid local minute.
2. `settings.rs`, `scheduler/model.rs`: validated independent intervals/toggles, work days/hours, app quiet mode, persisted pause, typed reminders/outcomes/actions/snapshots. Reject overnight work windows and invalid or unknown inputs.
3. `scheduler/engine.rs`: explicit pure transitions over injected time. One global open reminder, two-minute minimum delivery spacing, five-minute snooze and unanswered timeout. Complete/skip schedule from action time. Suppression closes open alerts as unanswered, never completed. Pause/resume and scheduling changes reset eligibility/deadlines without storms. Duplicate/stale action IDs fail.
4. `migrations/0002_scheduler.sql` and `storage/mod.rs`: preserve M1 data; atomically persist settings, both UTC deadlines/open IDs, supplementary open-reminder/cooldown metadata, and outcome events. Reject inconsistent recovery data. Commit before publishing. Runtime storage failure stops scheduling visibly.
5. `scheduler/service.rs`: one worker owns the engine and connection, serializing commands and ticks. Wait on a channel until the next relevant monotonic deadline, capped at 30 seconds to detect clock/timezone changes and suspend gaps. Recovery handles restart, >90-second sampling gaps, wall/monotonic drift, and timezone changes. Never replay backlog; select at most one eligible overdue category and reset other overdue deadlines.
6. `commands.rs`, `lib.rs`, `build.rs`, capabilities/permissions: real typed dashboard/settings/start/complete/skip/snooze/pause/resume commands; targeted typed scheduler, reminder, outcome, and settings events. Add only required command permissions and event listen/unlisten. No frontend event emission or plugin access.
7. `src/lib/`, `src/hooks/`, existing shell: typed APIs and a subscription installed before snapshot fetch; revision ordering prevents stale responses, cleanup handles unmount races. Display real scheduler status/deadlines without JS intervals. Preserve M1 visual identity. Explain that native alerts and break UI are not available.

Tests: both categories; interval validation; work days/end boundaries; quiet mode; snooze beyond work hours; all outcomes; unanswered timeout; duplicate actions; global overlap/spacing; manual/timed/tomorrow pause and persistence; settings changes; restart with future/overdue/open state; sleep with advancing or suspended monotonic clock; forward/backward wall changes; timezone/DST boundaries; no replay storms; storage rollback and reopen; fail-closed persistence; actor lifecycle; frontend event ordering/unmount cleanup/error handling. Use temporary DBs and fake clocks, not real waits for reminder intervals.

Run locked Cargo tests, formatting and Clippy, frontend unit tests/lint/typecheck/build, browser regression checks, and a Windows desktop command/event smoke check where tooling permits. Record exact failures and unverified physical sleep/timezone/native notification checks. Re-read PRD before later milestones.

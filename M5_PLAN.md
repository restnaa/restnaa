# M5 release audit plan

1. Inspect `PRD.md`, prior plans/evidence, Rust engine/clock/service/storage/native modules, React workflows, permissions, CSP and NSIS config. Inventory this Windows host and available clean-machine tooling read-only. Preserve existing app data and unrelated work. Do not change the machine clock, suspend the user's machine, sign out, disable global notifications, or change global DND merely to manufacture evidence; use deterministic tests and explicitly mark physical checks pending if unavailable.
2. `src-tauri/tests/scheduler.rs`, `scheduler_storage.rs`, `native.rs`, `history.rs`: execute full regression suites; add focused tests and repair actual findings in the corresponding modules. Cover both categories, restarts, manual/timed pause, suspend clock behaviors, forward/back/timezone/DST, no storms, stale actions, persistence failure and corrupt storage. Keep one Rust worker and no frontend scheduling timers.
3. `src-tauri/examples/notification_probe.rs`, release test helpers: improve installed notification evidence if needed so an old test toast alone cannot pass a fresh delivery check. Use official plugins and this app ID only. Test actual app permission denial through Windows settings if safely accessible, restore it, and keep fallback usable. No fake toast buttons, policy edits or DND bypass.
4. Installed native QA: actual tray menu Show/Settings/Pause/Resume/Open/Quit, close-to-tray, repeated launches, one process, opt-in startup registration and rollback/persistence, quiet startup, break UUID actions where eligible. Use native UI automation or installed webview IPC as evidence, clearly distinguish actual menu clicks from invoking the same command. Existing user history is never cleared for testing. Corrupt-data validation uses disposable files/profile or Rust tests, never the real user database.
5. Run `npm run lint`, `typecheck`, `test -- --run`, `build`; Rust fmt/strict Clippy/tests; Playwright desktop/compact/reduced motion, with compilation and browser suites sequential to avoid contention. Inspect rendered evidence and contrast/keyboard accessibility; repair concrete failures with targeted tests. Browser plugin absent: use Playwright/Edge. Run available lockfile dependency audits; document unavailable or failing audit tooling precisely.
6. Measure installed process-tree CPU and working/private memory over a documented idle interval, main hidden and both webviews included. Record sampling conditions and network sockets; don't infer battery life or long-term idle use. Keep benchmark artifacts/screenshots in temporary QA output; source reusable measurement helpers only where useful.
7. `src-tauri/tauri.conf.json`, installer hooks if needed, `.github/workflows/ci.yml`, release scripts: produce current-user NSIS, verify WebView2 strategy, startup/uninstall cleanup, signature status and SHA-256. Test install/upgrade/uninstall only in available appropriate environments. Do not uninstall/delete existing user data to claim a clean install. No clean Windows 10/11 or seven-day dogfooding claim without real evidence.
8. Deliver `RELEASE_NOTES.md`, `PRIVACY.md`, `docs/INSTALLATION.md`, `docs/KNOWN_LIMITATIONS.md`, `docs/RELEASE_AUDIT.md`, updated README/native checklist, installer and checksum. Audit report records exact commands, machine/tool versions, fixes, current observed evidence, pending tests and go/no-go. M5 authorizes these reviewable release documents, not publication/signing/deployment or invented clean-machine results.
